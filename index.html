🌳 PART A — Decision Tree Learning Concept-based

A1. Decision Tree Learning Algorithm

Definition A decision tree is a supervised learning method that approximates discrete-valued target functions, where the learned function is represented as a tree. It classifies an instance by sorting it down the tree from the root to a leaf, which provides the classification.
  • Each internal (decision) node tests one attribute of the instance.
  • Each branch from a node corresponds to one possible value of that attribute.
  • Each leaf node assigns a class label (the output).
  • A path from root to leaf = one conjunctive rule; the whole tree = a disjunction of conjunctions of attribute tests, so decision trees can represent any Boolean function.
Fig A1.1 — A learned decision tree for the classic "Play Tennis" problem (used later in the numericals).

General top-down induction approach (used by ID3, C4.5, CART)

  1. Start with all training examples at the root.
  2. Select the best attribute to split on (using a selection measure — info gain / gain ratio / Gini index).
  3. Partition examples into subsets, one per attribute value.
  4. Recurse on each subset, treating it as a new (smaller) tree-building problem.
  5. Stop when a node is pure (all examples same class), attributes are exhausted, or a stopping criterion is met.
Interview angle This is called greedy, recursive, top-down, divide-and-conquer search — four keywords examiners love asking about individually.

A2. Inductive Bias

Definition Inductive bias is the set of assumptions that, together with the training data, a learner uses to deductively justify the classifications it assigns to unseen future instances. Without some bias, a learner cannot generalise beyond the exact training examples it has seen.

Two types of bias (a favourite interview distinction)

TypeMeaningExample
Restriction biasRestricts the hypothesis space itself — only certain hypotheses can even be representedCandidate-Elimination: only conjunctive hypotheses allowed
Preference bias (search bias)Hypothesis space is complete, but the search prefers some hypotheses over othersID3: prefers shorter trees found earlier by the greedy search
ID3's approximate inductive bias "Shorter trees are preferred over larger trees. Trees that place high-information-gain attributes closer to the root are preferred over those that do not."
This is close to (but not identical to) Occam's Razor: "prefer the simplest hypothesis that fits the data."
  • ID3's hypothesis space (all possible decision trees) is complete relative to discrete-valued target functions — every finite discrete function can be represented by some tree.
  • So ID3 has (almost) no restriction bias — its bias is purely a preference bias coming from the order in which its greedy search explores hypotheses.

A3. Inductive Inference with Decision Trees

  • Inductive inference = generalising from a finite set of observed (specific) training examples to a general hypothesis that will hold on future, unseen examples.
  • ID3 can be viewed as searching a hypothesis space H (the space of all possible decision trees) for the hypothesis that best fits the training examples.

🌳 ID3 (decision trees)

Hypothesis space: complete (can express any discrete function)
Search: incomplete — greedy hill-climbing, no backtracking, single current hypothesis maintained

🔲 Candidate-Elimination

Hypothesis space: incomplete (restricted to conjunctions)
Search: complete — maintains the full version space, considers every consistent hypothesis
Consequence Because ID3's search is incomplete (greedy), it is not guaranteed to find the globally best (simplest / highest-gain) tree — it can get stuck in a locally good but globally sub-optimal tree. This is exactly why pruning (Section A7) is required afterwards.

A4. Entropy and Information Theory

Definition Entropy characterises the (im)purity/disorder of an arbitrary collection of examples. It tells us the minimum number of bits needed to encode the classification of an arbitrarily drawn member of the set S.
Entropy(S) = Σi=1c −pi log2(pi)

where c = number of distinct classes, and pi = proportion of examples in S belonging to class i.

  • Entropy = 0 when S is perfectly pure (all examples one class).
  • Entropy = 1 (maximum, for binary classification) when S is perfectly mixed (50–50 split).
  • For c classes, entropy ranges between 0 and log2(c).
  • Entropy is derived from information theory — it is the expected number of bits needed to encode the class of a randomly drawn example, using the optimal, shortest code based on the probability distribution of classes.
Fig A4.1 — Entropy vs. proportion p of positive examples (binary case): a peak of 1 at p = 0.5, zero at the pure ends.

A5. Information Gain

Definition Information Gain measures the expected reduction in entropy caused by partitioning the examples according to a given attribute A. ID3 picks, at every node, the attribute with the highest information gain.
Gain(S, A) = Entropy(S) − Σv∈Values(A) (|Sv| / |S|) × Entropy(Sv)

Values(A) = the set of all possible values of attribute A; Sv = subset of S for which A has value v.

✅ Numerical 1 — Gain(S, Outlook) on Play-Tennis dataset

Split by Outlook: Sunny (5, 2 Yes/3 No), Overcast (4, 4 Yes/0 No), Rain (5, 3 Yes/2 No).

Step 1: Entropy of each branch
Entropy(Sunny) = −(2/5)log₂(2/5) − (3/5)log₂(3/5) = 0.529+0.442 = 0.971
Entropy(Overcast) = 0 (pure, all Yes)
Entropy(Rain) = same computation as Sunny (3 Yes/2 No) = 0.971
Step 2: Weighted entropy after split
(5/14)(0.971) + (4/14)(0) + (5/14)(0.971) = 0.347 + 0 + 0.347 = 0.694
Step 3: Apply Gain formula
Gain(S,Outlook) = 0.940 − 0.694
Gain(S, Outlook) = 0.246 bits
✅ Numerical 2 — Gain(S, Wind) on the same dataset (compare against Outlook)

Split by Wind: Weak (8, 6 Yes/2 No), Strong (6, 3 Yes/3 No).

Step 1: Entropy of each branch
Entropy(Weak) = −(6/8)log₂(6/8) − (2/8)log₂(2/8) = 0.311+0.5 = 0.811
Entropy(Strong) = 3 Yes / 3 No → perfectly mixed → 1.0

Step 3: Apply Gain formula
Gain(S,Wind) = 0.940 − 0.892
Gain(S, Wind) = 0.048 bits — much lower than Outlook's 0.246, so Outlook is preferred at the root.
Interview angle Info gain is biased towards attributes with many distinct values (e.g. a "Date" or "ID" attribute would give perfect but useless splits). This exact weakness motivates Gain Ratio — see Section A7.

A6. ID3 Algorithm

ID3 (Iterative Dichotomiser 3, Quinlan 1986) is the classic greedy, top-down algorithm that builds a decision tree by recursively choosing the attribute with the highest information gain.

function ID3(Examples, Target_attribute, Attributes): Create a Root node for the tree if all Examples are positive: return Root labelled "+" if all Examples are negative: return Root labelled "−" if Attributes is empty: return Root labelled with most common Target value in Examples else: A ← the attribute from Attributes with highest Gain(Examples, A) Root's decision attribute ← A for each possible value vi of A: add a new branch below Root for A = vi Examples_vi ← subset of Examples where A = vi if Examples_vi is empty: add leaf labelled with most common Target value in Examples else: add subtree ID3(Examples_vi, Target_attribute, Attributes − {A}) return Root

A7. Issues in Decision Tree Learning

1. Overfitting the data

Problem A hypothesis h overfits the training data if some alternative h′ has more training error but less true (test) error. Decision trees can grow branches to fit noise or outliers, hurting generalisation.
  • Caused by: noisy training data, or too few examples resulting in coincidental regularities.

2. Approaches to avoid overfitting

✂️ Pre-pruning

Stop growing the tree earlier, before it perfectly classifies training data (e.g. stop if a node has too few examples, or gain is below a threshold).

🌲 Post-pruning

Grow the full tree first, then prune back nodes that do not improve accuracy on a held-out validation set. Generally works better in practice than pre-pruning.

Deciding correct final tree size uses one of:

  • Use a separate validation set to evaluate the effect of pruning.
  • Apply a statistical test (e.g. chi-square) to check whether a split is statistically significant.
  • Use an explicit measure of complexity like MDL (Minimum Description Length) — minimise size(tree)+size(misclassifications).

Reduced-Error Pruning

  • Consider each decision node as a candidate for pruning.
  • Pruning = removing the subtree rooted at that node, making it a leaf with the majority class.
  • Remove the node only if the resulting (pruned) tree performs no worse on the validation set than the original.
  • Repeat, always greedily removing the node whose removal most improves validation accuracy, until further pruning is harmful.

Rule Post-Pruning (used in C4.5) — most widely used in practice

  1. Grow the tree fully (allow overfitting).
  2. Convert the tree into an equivalent set of rules — one rule per root-to-leaf path.
  3. Prune each rule independently by removing preconditions that do not reduce estimated accuracy.
  4. Sort the pruned rules by estimated accuracy, and apply them in that order at classification time.
Why convert to rules first? It lets each path be pruned independently (a condition can be dropped from one rule without affecting sibling branches), gives more fine-grained pruning, and rules are far more human-readable than a tree — good for interviews!

3. Incorporating continuous-valued attributes

  • ID3 originally handles only discrete attributes. For a continuous attribute A, create a Boolean test "A < threshold c" (dynamic discretization).
  • Best threshold: sort examples by A; consider candidate thresholds midway between consecutive examples whose class labels differ; evaluate information gain for each candidate; pick the best.

4. Alternative attribute-selection measures — Gain Ratio

Problem with plain Information Gain Gain is biased toward attributes with many values (e.g. "Date"), which can produce many small, pure — but useless — subsets, leading to overfitting.
GainRatio(S, A) = Gain(S, A) / SplitInformation(S, A)
SplitInformation(S, A) = −Σi (|Si|/|S|) log2(|Si|/|S|)

SplitInformation penalises attributes that split S into many small subsets — used in C4.5 instead of plain Gain.

5. Handling training examples with missing attribute values

  • Assign the most common value of that attribute at that node.
  • Or assign the most common value among examples with the same target class at that node.
  • Or (more sophisticated) assign a probability to each possible value and distribute the example fractionally across all branches — used by C4.5.

6. Handling attributes with differing costs

  • In some domains (e.g. medical diagnosis), attributes have different costs (e.g. a blood test costs more than checking temperature).
  • Bias the attribute selection to favour low-cost attributes wherever possible — e.g. divide Gain by Cost, or use Gain²/Cost (Tan & Schlimmer), or (2Gain−1)/(Cost+1)w (Nunez).
Interview angle — most-asked issue If asked "what is the single biggest practical issue with decision trees?" → Overfitting, solved via pruning, is almost always the expected top answer.

A8. Interview Questions — Decision Trees

Q1. Why does ID3 prefer attributes with higher information gain?
Because higher gain means a bigger reduction in entropy/uncertainty — the resulting subsets are purer, so fewer additional splits (and less depth) are needed to classify examples, giving a shorter, simpler tree — matching ID3's inductive bias.
Q2. What's the difference between ID3, C4.5, and CART?
ID3: only discrete attributes, uses Information Gain, no pruning built-in. C4.5: handles continuous attributes and missing values, uses Gain Ratio, includes rule post-pruning. CART: builds binary trees only, uses the Gini Index (classification) or variance reduction (regression), supports both classification and regression.
Q3. Why is entropy maximum at p = 0.5 for two classes?
Because that is the point of maximum uncertainty — you have the least ability to predict the class of a random example, so the most bits are needed, on average, to encode/communicate the outcome.
Q4. Is ID3 guaranteed to find the smallest possible decision tree?
No — ID3 performs a greedy, hill-climbing search with no backtracking, so it can converge to a locally optimal tree rather than the globally smallest one consistent with the data.
Q5. What happens if Attributes is empty but examples are still mixed?
A leaf is created and labelled with the majority (most common) target class among the remaining examples — this is a form of "tie-breaking" / noise handling.
Q6. Why do we need Gain Ratio instead of just Information Gain?
Plain Gain is biased toward high-cardinality attributes (like unique IDs) which trivially create pure but useless splits. Gain Ratio normalises Gain by SplitInformation to remove this bias.
Q7. What is the difference between pre-pruning and post-pruning?
Pre-pruning stops tree growth early using a stopping condition (faster, but risk of stopping too soon — "horizon effect"). Post-pruning grows the full tree and then removes branches that don't help validation accuracy — usually gives better trees, at higher computational cost.
📍 PART B — Instance-Based Learning Lazy learners

B0. What is Instance-Based Learning?

Definition Instance-based learning methods simply store the training examples. Generalisation is postponed until a new query instance must be classified — at that point, the stored instances are examined to relate them to the new instance ("lazy" evaluation).
  • Also called lazy learners, as opposed to eager learners (e.g. decision trees, neural nets) which build an explicit generalised model at training time.
  • Includes: k-Nearest Neighbour, Locally Weighted Regression, Radial Basis Function networks (partially), Case-Based Reasoning.

🐢 Lazy learner (e.g. k-NN)

Little/no work at training time; all the work (search + computation) happens at query/classification time; can approximate the target function locally and differently for each query point.

🐇 Eager learner (e.g. Decision Tree)

Builds one global approximation of the target function during training; classification of a query is then very fast, but the model may not fit local regions of the space as well.
Key disadvantage Cost of classifying a new instance can be high (must search/compare against many/all stored examples) and instance-based methods typically consider all attributes, so they are vulnerable to the curse of dimensionality — irrelevant attributes can dominate the distance computation.

B1. k-Nearest Neighbour Learning

Definition The most basic instance-based method. It assumes all instances correspond to points in n-dimensional space ℝⁿ. To classify a new query instance, k-NN finds the k training examples nearest to it (usually by Euclidean distance) and assigns the majority class among them.
d(xi, xj) = √( Σr=1n (ar(xi) − ar(xj))² )  // Euclidean distance over n attributes
function k-NN(TrainingSet, query x_q, k): for each training example x_i: compute distance d(x_i, x_q) select the k examples with smallest distance return the class that is the majority among those k neighbours
  • Distance-weighted k-NN: give each neighbour a vote weighted by 1/d² (closer neighbours count more) — reduces sensitivity to the exact choice of k, and even allows k = "all training examples" (a global weighted vote, called Shepard's method).
  • k-NN can also do regression — instead of majority voting, average (or weighted-average) the target values of the k neighbours.
  • The decision boundary formed by 1-NN is a Voronoi diagram partitioning the space around each stored point.
Interview angle Curse of dimensionality: as the number of irrelevant attributes grows, distances become dominated by noise from those irrelevant dimensions, and the "nearest" neighbours stop being meaningfully similar. Fix: attribute weighting, or feature selection before applying k-NN. Also — always normalise/scale features before computing distance, or attributes with larger numeric ranges will dominate.

B2. Locally Weighted Regression (LWR)

Definition LWR is a generalisation of k-NN regression. Instead of using only the k nearest neighbours with equal weight, it uses all (or nearby) training points, each weighted by a kernel function of its distance to the query point — nearby points get high weight, far points get near-zero weight — and fits a local model (often a simple weighted average, or a local linear regression) around the query.
wi = K(d(xq, xi))  =  exp( −d(xq,xi)² / (2σ²) )  // Gaussian kernel, bandwidth σ
ŷ(xq) = Σ wi yi / Σ wi  // locally weighted average (order-0 fit)
  • The full "locally weighted linear regression" fits a local straight line (minimising Σwi(yi − w0 − w1xi)²) around xq, rather than only a weighted average — more accurate but more computation.
  • σ (bandwidth) controls the "locality": small σ → very local, wiggly fit (risk of overfitting); large σ → smoother, more global fit (risk of underfitting) — directly analogous to the role of k in k-NN.
  • Like k-NN, LWR is lazy: the local model is only built when a query arrives.

B3. Radial Basis Function (RBF) Networks

Definition An RBF network is a type of artificial neural network that uses radial basis functions (typically Gaussians) as activation functions in a single hidden layer. It combines instance-based learning (the hidden units are centred at, or near, training instances) with global approximation (a linear output layer).
Fig B3.1 — RBF network: inputs → Gaussian hidden units centred at prototypes ci → linearly combined output.
φi(x) = exp( −‖x − ci‖² / (2σi²) )  // hidden unit i, centre c_i, width σ_i
f(x) = w0 + Σi=1k wi φi(x)  // output = linear combination of hidden activations

Training an RBF network (two-stage, faster than backprop)

  1. Choose the centres ci — either use all/some training instances directly, or cluster the inputs (e.g. k-means) and use cluster centroids.
  2. Choose widths σi — often fixed (e.g. based on distance to nearest centres).
  3. Solve for output weights wi — since the output layer is linear, this reduces to a simple (global) least-squares linear regression problem over the hidden-layer outputs.
Interview angle RBF networks are a nice bridge topic: they are instance-based (centres are training points / local Gaussian "receptive fields", like k-NN) but also eager/global (a trained set of weights is used for every future query, unlike pure lazy k-NN). Compared to standard backprop MLPs, RBF networks usually train much faster since only the output layer needs iterative/least-squares fitting.
✅ Numerical 1 — Forward pass with 2 centres (1-D input)

Centres: c₁=2, c₂=8, σ=2 for both. Trained weights: w₀=1, w₁=3, w₂=2. Compute output for input x=5.

B4. Case-Based Learning (Case-Based Reasoning, CBR)

Definition Case-Based Reasoning is an instance-based learning method where instances ("cases") are represented using rich, structured (often symbolic) descriptions instead of just points in ℝⁿ, and where the retrieval/matching process can involve more elaborate, knowledge-based similarity and adaptation methods rather than a simple Euclidean distance.
Fig B4.1 — The CBR cycle: the "Four R's" — Retrieve, Reuse, Revise, Retain.

The Four R's of the CBR cycle

  • Retrieve — given a new problem, find the most similar case(s) from the case library.
  • Reuse — map/adapt the solution from the retrieved case(s) to the new problem.
  • Revise — test the proposed solution in the real world (or simulation) and repair it if it fails.
  • Retain — store the new, validated case (problem + solution) for future reuse — this is how CBR systems "learn" incrementally over time.

How CBR differs from plain k-NN

Aspectk-NNCase-Based Reasoning
Case representationNumeric feature vectorRich symbolic/structured description (graphs, rules, relations)
SimilaritySimple metric (Euclidean, etc.)Complex, possibly knowledge-guided similarity
Use of retrieved caseDirect averaging/votingExplicit adaptation/reasoning step ("Reuse"/"Revise")
  • Applications: legal reasoning (precedent-based judgments), medical diagnosis support systems, help-desk / customer-support systems, mechanical/engineering design (e.g. the classic CADET system for conceptual design reuse), and recommendation systems.

B5. Interview Questions — Instance-Based Learning

Q1. Why is k-NN called a "lazy" learner?
Because it does no explicit training/model-building step — it just stores the training data, and defers all computation (distance calculation, voting) to the moment a query needs to be classified.
Q2. What is the time complexity of classifying one query with basic k-NN?
O(n·d) to compute distances to all n training points across d features, plus O(n log k) or O(nk) to find the k smallest — much more expensive at prediction time than eager learners like decision trees.
Q3. How do you choose a good value of k?
Too small k (e.g. 1) is sensitive to noise/outliers (high variance); too large k over-smooths and can include points from other classes (high bias). Typically chosen via cross-validation; an odd k is preferred for binary classification to avoid ties.
Q4. How does Locally Weighted Regression relate to k-NN?
LWR generalises k-NN regression: instead of a hard cutoff at k neighbours with equal weight, it uses a smooth kernel function (e.g. Gaussian) to softly weight ALL points by distance — so it's a smoother, more principled version of the same "local averaging" idea.
Q5. Why do RBF networks train faster than standard backpropagation MLPs?
Because once the hidden-layer centres and widths are fixed (via clustering or heuristics), computing the output-layer weights reduces to solving a single linear least-squares problem, instead of iterative gradient descent through multiple non-linear layers.
Q6. What is the curse of dimensionality, and why does it hurt instance-based methods specifically?
As dimensionality grows, all points tend to become nearly equidistant from each other, and irrelevant attributes add noise to the distance measure — since instance-based methods rely directly on distance in the full feature space, their notion of "similarity"/"nearness" becomes unreliable.
Q7. When would you prefer Case-Based Reasoning over k-NN?
When cases are naturally structured/symbolic (not simple numeric vectors) and solutions need explicit adaptation logic rather than pure averaging — e.g. legal precedent reasoning, engineering-design reuse, or diagnosis systems requiring a "repair" step after retrieval.
